01 · Quick start

Use the full SDK archive for all sample fields, or the source archive for reference generation and development. No Rust build is needed for the offline film or independent JS cloud/fog examples.

Open the hosted example gallery, or run a local static server from the repository root:

python -m http.server 8000 --bind 127.0.0.1

Navigate to http://localhost:8000/examples/. The standalone examples/airborne-smoke/index.html also opens directly. Other browser examples use ES modules and HTTP.

02 · JavaScript / TypeScript

Independent CPU reference generation, with the actual public JS implementation. This is not Rust WASM.

import { generateFidelityVolume, getFidelityPreset,
         prepareFidelityVolume } from './bindings/web/fidelity.mjs';

const field = generateFidelityVolume('cumulus_cloud', {
  cells: [72, 36, 48], extent: [144, 72, 96]
});
const style = getFidelityPreset('cumulus_cloud', 'medium');
const prepared = prepareFidelityVolume({
  ...field, material: style.material, ...style.lighting
});
const frame = prepared.render({
  eye: [110, 15, -150], target: [72, 32, 48],
  width: 320, height: 200, steps: 96, background: 'sky'
});
// frame.rgba: display-ready RGBA8

Run the above as an ES module. Type declarations are in bindings/web/. Use the CPU reference viewer to explore settings.

03 · Python

Python 3.11+ is recommended for project tools. The pure-data reader needs no compiled native library.

python -m pip install -e bindings/python
from vapor_game.field_asset import read_field_asset

field = read_field_asset('assets/field-assets/cloud.vpf')
print(field.cells, field.extent, field.time)
# field.density and field.temperature are Float32 arrays.

Actual Rust CPU via Python

Install Rust 1.88+ and your platform linker first. The wrapper uses the actual compiled library; it cannot silently substitute the independent Lab.

python tools/build.py --native --test
python examples/python/offscreen.py

04 · Rust, WASM and GPU

Build Rust on a suitable machine. A successful build in your environment is required before relying on the native solver. CPU native and WASM can be built without a hardware GPU; the GPU path requires wgpu dependencies and a compatible device.

# Native CPU
python tools/validate_runtime.py --build --modes cpu --capture

# CPU WASM
rustup target add wasm32-unknown-unknown
python tools/build.py --web
python tools/validate_wasm_fidelity.py

# GPU / one-way Hybrid
python tools/build.py --native --gpu --test --stage-adapters
python tools/validate_runtime.py --modes gpu hybrid --capture

Actual WASM cloud API (after building):

import { loadVapor } from './bindings/web/vapor.mjs';
import { NativeFidelityCPU } from './bindings/web/native-fidelity.mjs';
const native = new NativeFidelityCPU(await loadVapor());
const cloud = native.generate('cumulus_cloud', {
  cells: [32, 16, 24], extent: [48, 24, 36]
});
const frame = native.render(cloud, {
  width: 96, height: 60, steps: 64,
  eye: [30, 8, -50], target: [24, 12, 18]
});

Native Rust source example

Build with the vapor-core crate from this workspace. This is a source snippet, not an executed native sample in this delivery.

use vapor_core::{Config, Simulation};

let mut sim = Simulation::new(Config::default())?;
sim.step_fixed(1)?;
let metrics = sim.metrics();

The Rust core is a Cargo workspace under crates/. See docs/API_CONTRACT_KO.md for the source API and experimental M2 constructors. CPU / GPU / Hybrid are separate paths. Hybrid is one-way coarse CPU velocity → GPU fine scalar, not a coupled two-way solver.

05 · Portable volume assets

VPF1 stores x-fastest planar Float32 density and temperature, extent and time; VPA1 indexes time-ordered VPF1 snapshots. Scene lighting and material are stored separately. CRC detects accidental data corruption, not authenticity.

from vapor_game.field_sequence import FieldSequence

sequence = FieldSequence.open('assets/cloud-motion/sequence.vpa')
field = sequence.sample(3.25)
print(field.cells, field.time)

Use the full SDK package for the referenced paths. The renderer controls optical appearance; data parity does not prove pixel parity between engines.

C# / .NET

After building the native library, use the supplied .NET sample with the matching platform library on the loader search path. Example source:

using VaporGame;
var cfg = Config.Default;
cfg.Nx = 12; cfg.Ny = 16; cfg.Nz = 12;
cfg.CellSize = .05f;
using var sim = new Simulation(cfg);
var emitter = Emitter.Default;
emitter.Position = new Float3(.3f, .1f, .3f);
sim.SetEmitter(0, emitter);
sim.Step(60);

See examples/dotnet/Program.cs and adapters/unity/README.md. C# compilation is pending.

No engine editor has been verified in the delivery environment. The full repository includes each adapter's README with detailed setup.
